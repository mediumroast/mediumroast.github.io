# Open Source Page Rebuild — Plan

## Context

The live site (http://mediumroast.github.io) is generated by **Blocs**, a Mac
GUI site-builder, from `Open Source at Mediumroast.bloc` (binary plist) and
exported into `docs/`. Since we have no way to script the Blocs app, and the
current markup is bloated/awkward (fixed-height cards, duplicate element IDs,
Bootstrap+Blocs cruft), we're **rebuilding the page from scratch as hand-authored
static HTML/CSS**, dropping the `.bloc` project as the source of truth going
forward. `docs/` remains the GitHub Pages publish directory.

## Current state (verified against the live site)

Live page = `docs/index.html` exactly, one flat grid of four cards:

- `mediumroast_js` — Node.js CLI/SDK
- `mediumroast_py` — Python SDK
- `company_dns` (personal account `miha42-github`, not `mediumroast` org)
- `mr_markdown_builder`

## Plan

1. **Author a new static page from scratch** (`docs/index.html` +
   `docs/style.css`, replacing the Blocs output):
   - Drop Bootstrap/Blocs/feather/fontawesome dependencies unless something
     specific is still needed (icons for GitHub/npm/PyPI links can be simple
     inline SVGs instead of an icon-font bundle).
   - Semantic structure: header/nav, intro, `<section>` per status group, footer.
   - Two sections: **Active** and **Incubating**, each a card grid, in that
     order (Active first).
   - Incubating cards (`mediumroast_js`, `mediumroast_py`, `mediumroast_api`)
     get a visible status badge/pill plus one neutral, generic line: "Currently
     in incubation — not under active development; APIs may change without
     notice."
   - Fix the duplicate-`id` bug from the old markup; no repeated anchors.

2. **Style using the manifold UX style guide as source of truth**
   (`/Users/mihay42/dev/manifold/wiki/guides/ux/style-guide.md`), ported to
   plain CSS custom properties since this site has no component framework:
   - Color tokens: brand dark `#0F0D0E`, brand orange `#DC7D00`, tech cyan
     `#00A8D2`, light blue `#DCE9F6`, warm off-white `#FFF3EF`, neutral grays
     `#D4D7DD` / `#88737E`. This **replaces** the current gold `#CD9037` accent
     — page moves onto the same palette as mediumroast.io.
   - Type: `"Helvetica Neue", Helvetica, Arial, sans-serif` for UI text,
     `Georgia, serif` for any display/serif use, weight scale `300/400/700/900`.
   - Spacing scale `4/8/16/24/32/48/64/96`; container width `1140px` with the
     guide's `min(1140px, calc(100% - 40px))` rule.
   - Radius/elevation tokens: `--radius-sm 12px`, `--radius-md 20px`,
     `--radius-lg 28px`, pill controls at `999px`, soft/card shadows.
   - Card, button (`primary`/`secondary`/`card-action`), and badge treatment
     modeled on the guide's component library, adapted to a static (non-React)
     page — no auth states or forms apply here, so most of the guide's
     interaction-pattern section is out of scope.
   - Incubating badge/pill is a new component (not in the guide) — style it
     consistent with the guide's card/button visual language (muted neutral
     tone, not a warning color, since incubation isn't an error state).

3. **Responsive check** at the guide's key breakpoints (980px / 720px / 640px):
   multi-column grid collapses to single column, badges/links wrap cleanly.

4. **Accessibility basics**: visible focus states on links/cards, sufficient
   color contrast for badges, semantic headings (`h1` → `h2` per card).

5. **Verify locally** by serving `docs/` and checking both sections and all
   three breakpoints in-browser before calling it done.

6. **Deprecate the Blocs project**: remove `Open Source at Mediumroast.bloc`
   from the repo (git history retains it if ever needed) and add a short note
   (README or comment) that `docs/` is now hand-authored static HTML/CSS —
   no Blocs app, no re-export step.
